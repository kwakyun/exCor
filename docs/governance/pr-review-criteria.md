# PR Review Agent 판정 및 검토 기준 (PR Review Criteria)

PR Review Agent는 코드 변경 사항이 포함된 모든 Pull Request에 대해 아래 10대 핵심 항목을 검토하고 5단계 등급으로 평가합니다.

---

## 1. 10대 점검 체크리스트

1. **Issue 일치성**: 연결된 Issue와 Acceptance Criteria(완료 조건)가 명시되어 있는가?
2. **범위 준수**: 실제 변경 사항이 승인된 Issue 작업 범위를 이탈하지 않았는가?
3. **예외 처리**: 요구사항의 정상 흐름뿐 아니라 실패 흐름, 경계값(Boundary)이 올바르게 처리되었는가?
4. **테스트 검증**: 단위/통합 테스트가 존재하며 실제 변경 내용을 정확히 검증하는가?
5. **CI 파이프라인**: 린트, 타입체크, 빌드, 테스트 등 모든 CI 검증이 정상 통과했는가?
6. **보안 및 Secret**: Secret, API Key, 패스워드, 개인정보(PII)가 노출되지 않았는가?
7. **고위험 요소**: 인증, 권한, 결제, DB, 인프라, 환경변수 구조 변경이 포함되어 있는가?
8. **하위 호환성**: API Breaking Change 가능성이 존재하는가?
9. **불필요한 변경**: 과도한 의존성 추가나 무관한 대규모 리팩터링이 섞여 있지 않은가?
10. **Rollback 현실성**: 비상 상황 발생 시 되돌릴 수 있는 Rollback 절차가 현실적인가?

---

## 2. 5단계 판정 등급 (Rating Levels)

| 등급 | 정의 | 조치 |
|---|---|---|
| **Blocker** | 보안 취약점, 데이터 손실 위험, 서비스 장애 유발, 병합 불가 결함 | **머지 절대 불가**. 즉시 반려 및 수정 지시 |
| **Required** | Issue 완료 조건 미달, 테스트 누락, 문서 미반영, 필수 예외처리 누락 | **머지 불가**. Developer Agent가 보완 후 재검토 |
| **Warning** | 병합은 가능하나 잠재적 성능/유지보수 위험이 있는 코드 | 사람 리뷰어 검토 필요 |
| **Suggestion** | 가독성 개선, 컨벤션 미세 조정 등 권장 사항 | 권장 사항 전달 (병합을 차단하지 않음) |
| **Info** | 단순 참고 정보 및 변경 맥락 요약 | 정보 공유 |

> **[원칙]**
> `Blocker` 또는 `Required` 판정이 1개라도 있는 경우:
> - 사람에게 Approve를 요청하지 않습니다.
> - 수정 항목을 정리하여 Developer Agent에 전달하고, 재구현 후 CI/Review/QA를 처음부터 다시 수행합니다.
