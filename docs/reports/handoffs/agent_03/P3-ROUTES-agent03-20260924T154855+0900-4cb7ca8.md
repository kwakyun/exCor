## remaining_risks

- `NODE_ENV` 미설정(개발 기본값)에서는 mock 방문 승인 route가 그대로 노출된다. 실제 배포
  파이프라인이 `NODE_ENV=production`을 확실히 설정한다는 전제에 의존한다 — 이 전제 자체는
  03의 검증 범위 밖(배포/ENV 설정은 02/01 영역).
- `EnvIssuerSigner.fromEnv()`가 프로세스 시작이 아니라 **첫 stamps 요청 시점**에 평가된다.
  즉 서버가 정상 기동돼도 `STAMP_ISSUER_PRIVATE_KEY`가 나중에 누락된 걸 알게 되는 시점이
  "첫 요청"이라 조기 경보(헬스체크)는 아직 없다. 별도 startup healthcheck는 범위 밖으로 남김.
- `chain/deployments/local-31337.json` 파일 자체가 없거나 파싱 실패해도 동일하게
  `STAMPS_UNAVAILABLE`로만 보고된다(초기화 실패 원인이 "서명자 키 누락"인지 "배포 metadata
  누락"인지는 서버 로그의 `stampsInitError.message`로만 구분 가능, 응답 바디에는 노출하지
  않는다 - api-v1.md "내부 상세 미노출" 원칙을 따랐다).
- StampsRepository가 in-memory이므로 여러 서버 인스턴스(수평 확장) 환경에서는 세션/challenge
  공유가 되지 않는다 — 로컬 단일 프로세스 데모 전용이라는 기존 P3-04 handoff의 remaining_risks
  와 동일한 한계를 그대로 상속한다.
